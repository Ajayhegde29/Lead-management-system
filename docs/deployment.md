# Deployment guide

## Production prerequisites

1. Create a MongoDB Atlas cluster and database user.
2. Allow network access from the backend hosting platform (or temporarily allow all while evaluating).
3. Keep the MongoDB URI and JWT secret private; add them only through host environment-variable settings.

## Backend on Render

The repository includes `render.yaml`. In Render, choose **New → Blueprint** and connect this repository. Render detects the Node web service in `server/`.

Set these secure values before deployment:

| Variable | Value |
| --- | --- |
| `MONGODB_URI` | MongoDB Atlas connection string |
| `CLIENT_URL` | Deployed Vercel frontend origin, for example `https://lead-management.example.vercel.app` |

`JWT_SECRET` is generated by the blueprint. `PORT`, `NODE_ENV`, and `JWT_EXPIRES_IN` are supplied by the blueprint. Confirm the health check returns `200` at `/api/health`.

To support more than one allowed frontend origin, set `CLIENT_URL` as a comma-separated list with no spaces required, for example:

```text
https://app.example.com,https://staging.example.com
```

## Frontend on Vercel

1. Import the same repository into Vercel.
2. Set the Vercel project root directory to `client`.
3. Vercel detects the Vite build command (`npm run build`) and output directory (`dist`).
4. Add the environment variable below, then deploy:

```text
VITE_API_URL=https://your-render-service.onrender.com/api
```

After Vercel assigns a production URL, update Render’s `CLIENT_URL` to that exact origin and redeploy the backend if necessary.

## Release checklist

- Run `npm test` and `npm run lint` in `server`.
- Run `npm run lint` and `npm run build` in `client`.
- Seed the production admin only through a controlled operational step, not a public endpoint.
- Verify login, lead creation, follow-up creation, dashboard counts, and logout using the deployed URLs.
- Never upload `.env` files or expose a JWT token in screenshots, source control, or public documentation.
